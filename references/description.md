# description

## 扱うこと

description を書くとき、何をどの形で書くか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 3-4 を写した。（出典：人の判断を切り出すAIスキルの設計_v2.0.0 の3-4@2026-10-29）

### 1. 文脈・種類・使う場面の3項目を、引用符で囲んだ1行に書く

項目を固定し、引用符で囲んだ1行に「。」で区切って書く。

```yaml
description: "文脈: <区切られた文脈>。種類: <アプリケーションスキル / 中核判断 / 一般的な業務知識>。使う場面: 名前で指名されたときだけ使い、会話の内容からは選ばない。"
```

1. （知見）YAMLでは、コロンの後ろに空白がある値を引用符で囲まないと、構文エラーになる。（出典：なし）
2. （根拠）どのスキルも名前で指名して使うので、description は、AIが会話の話題からスキルを勝手に読み込むのを防ぐことと、人がスキルを見分けることに使う。（決定日：記録なし）

### 2. 使う場面は、どのスキルも同じ定型文にする

使う場面は、どのスキルも「名前で指名されたときだけ使い、会話の内容からは選ばない。」にする。

1. （根拠）会話の内容から選ばせると、頼んでいないスキルの判断や手順が会話に混ざる。（決定日：記録なし）

### 3. 文脈は、紛れない粒度で書く

文脈と種類は、名前からも読めるが、書く。文脈は、紛れない粒度で書く。

1. （根拠）名前の規則に従わないスキルと並べたときにも、見分けられるようにする。（決定日：記録なし）

### 4. 本文に書いたことを繰り返さない

呼ばれる場面・目的・手順・作り・依存するスキル・データの出所・持たないもの・「必ず使う」などの強調を書かない。書くかどうかは、「この文を消したら、AIの選び方が変わるか」で決める。指名し忘れたときの備えは、導入先の常に読まれる指示のファイル（`AGENTS.md` など）に書く。

1. （原因）description に何をするか・呼ばれ方・作り・依存するスキルを書き足していったら、500文字近くまで膨らみ、本文の目的とも重複した。（発生日：記録なし）
