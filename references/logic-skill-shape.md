# ロジックスキルの型

## 扱うこと

ロジックスキルの SKILL.md を書くとき、どの章を置き、索引をどう書くか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 4章の前置き・4-1・4-2 を写した。（出典：人の判断を切り出すAIスキルの設計_v2.0.0 の4章・4-1・4-2@2026-10-29）

### 1. 1つのロジックスキル＝1つの区切られた文脈にする

1つのロジックスキル＝1つの区切られた文脈。その文脈の判断を複数持ち、`references/` に1判断1ファイルで分ける。SKILL.md は判断の中身を持たず、索引から判断ファイルへ辿らせる。判断に要る計算もロジックスキルが持つ（`scripts/`）。判断どうしは、答えで結ぶ。

1. （根拠）計算をアプリケーションスキルに置くと、判断の一部がそこに固定される。（決定日：記録なし）

### 2. フォルダと章を、種類ごとの型で置く

フォルダは、`SKILL.md`・`README.md`・`LICENSE`・`references/<判断>.md`・`scripts/` で構成する。SKILL.md は、frontmatter のあとに、種類ごとの章をこの順で `#` の見出しにして書く。本文全体のタイトルと、目的の章は置かない。

| 種類 | 章 | frontmatter の metadata |
|---|---|---|
| core-logic | 判断定数 `core-logic の章` | 判断定数 `core-logic の metadata` |
| generic-logic | 判断定数 `generic-logic の章` | 判断定数 `generic-logic の metadata` |

「手続きに使う道具」の章には、モジュールの一覧と役割・import の仕方・例外の一覧・シェルから起動するスクリプトの一覧と共通の約束を書き、関数の一覧は書かない。種類で持たないと決まっている章だけを置かず、そのほかの章は、中身が無くても置いて「なし」と書く。他のスキルに依存しないので、`dependencies` は持たない。

1. （根拠）目的を持ち、そのために判断を聞くのはアプリケーションスキル。何に答えるかは、判断ファイルと索引の「扱うこと」が持つ。（決定日：記録なし）

### 3. 索引は1行＝1判断＝1ファイルにし、判断定数 `索引の列` で書く

索引は、1行＝1判断＝`references/` の1ファイルにし、判断定数 `索引の列` をこの順で、どの列も省かずに書く。当てはまらない所は `—`。

| 列 | 書くこと |
|---|---|
| 判断名 | 短い名詞句。依存する判断や本文からは、この名前で指す |
| 扱うこと | 判断ファイルの「扱うこと」と同じ文。答え方は書かない。作業の場面で絞られるときは、頭に「〜するとき、」を付ける |
| ファイル | `[plateau.md](references/plateau.md)` の形の相対リンク |
| 依存する判断 | 答えを材料にする、このスキルの別の判断の判断名。複数は「・」で区切る |
| 計算 | `judge.py` で計算する判断は `○`。第1引数に、その判断のファイル名で渡せる |

依存は「依存する判断」の列だけが持ち、行の並びや別の章で依存の順を書かない。判断を足す・消す・改名するときと、扱うことを直すときは、判断ファイルと索引の行を一緒に直す。

1. （根拠）扱うことに答え方を書くと、判断を直したときに2か所を直すことになり、直し漏れた索引の答え方でAIが答えてしまう。依存を2か所に書くと、判断を足したときに食い違う。（決定日：記録なし）
2. （原因）索引の「いつ聞くか」で、作業の前に自分から判断を聞かせようとしたが、スキルは読み込まれなかった。場面は扱うことに入れて、索引を1列にした。（発生日：記録なし）

## 判断定数

| 名前 | 値 | 単位 | 理由 |
|---|---|---|---|
| core-logic の章 | 索引、このスキルの設計上の決まりごと | 見出し | 答え方2の理由1と同じ |
| generic-logic の章 | 索引、手続きに使う道具、このスキルの設計上の決まりごと | 見出し | 答え方2の理由1と同じ |
| core-logic の metadata | version、repository、author、design、design-url | キー | 記録なし |
| generic-logic の metadata | version、repository、design、design-url | キー | 記録なし |
| 索引の列 | 判断名、扱うこと、ファイル、依存する判断、計算 | 列 | 答え方3の理由1と同じ |
| core-logic の定型文の項目数 | 5 | 項目 | 記録なし |
| generic-logic の定型文の項目数 | 6 | 項目 | 記録なし |

## 求める材料

| 材料 | 種類 | 必須 | 形 | 無いとき |
|---|---|---|---|---|
| `種類` | 対象の属性 | ○ | `"core-logic"`/`"generic-logic"`。スキルの種類 | 判断できない |
| `ファイル` | 対象の記録 | ○ | `{"SKILL.md": "<本文>", "README.md": "<本文>", "references/plateau.md": "<本文>"}`。スキルのファイルのパスと本文。LICENSE は中身が空の文字列でよい | 判断できない |

## 計算

`judge.py logic-skill-shape` が、frontmatter の metadata のキー・章の並び・定型文が「SKILL.md に入れる文」の定型文と同じか・判断定数 `索引の列`・索引とファイルの1対1・README の章・LICENSE の有無を確かめ、`{"問題": [{"ファイル", "内容"}]}` を返す。扱うことの書き方が合っているかは計算しない（AIが当てはめる）。
