# 依存の宣言とバージョン

## 扱うこと

依存するスキルを書くとき・判断ファイルを変えたとき、バージョンの範囲とバージョンをどう上げるか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 1-1 の依存の向きと、6-4 のバージョンの規則と 6-8 を写した。（出典：S1）
- （知見）バージョンの範囲と比べる値は、設計文書の 6-8 を写した。（出典：S2）
- （知見）「バージョン」の言葉は、設計文書の 6-4 と 6-8 を写した。（出典：S3）

### 1. 依存は、frontmatter の `metadata.dependencies` に書く

アプリケーションスキルは、委任表・参照表・依頼表に出てくるスキルを、すべて `metadata.dependencies` に書く。本文には置かない。ロジックスキルは依存の宣言を持たない。

```yaml
metadata:
  dependencies: >-
    github:<owner>/diet-process-<作成者>-core-logic-skill@^0.2.0,
    github:<owner>/collect-oura-records-app-skill@^0.2.0
```

| 項目 | 書き方 |
|---|---|
| 1件の形 | `github:<owner>/<repo>@<バージョンの範囲>` |
| 複数のとき | `,` で区切って1つの文字列に並べる。YAMLのリストは使わない。長くなるときは `>-` で複数行に分けてよい |
| バージョンの範囲 | npm の書き方で、`^` を使う（`^0.2.0` は 0.3.0 未満、`^1.2.0` は 2.0.0 未満）。範囲は、依存先の `metadata.skill-version` と比べる |

1. （原因）使用するリポジトリ表を SKILL.md の本文に置いたら、実行のたびには使わない表が、スキルを呼ぶたびに読み込まれていた。（発生日：記録なし）
2. （知見）`metadata` の値は文字列だけ。（出典：なし）

### 2. 判断ファイルを変えたら、ロジックスキルのバージョンを上げる

判断ファイルを変えたら、ロジックスキルのバージョンを上げる。バージョンが依存の宣言の範囲を超えたときは、それを参照するアプリケーションスキルの手順や材料を合わせてから、範囲を更新する。範囲の中で上がったときは、アプリケーションスキルを直さない。

1. （根拠）依存の向きがアプリケーションスキルからロジックスキルへの一方向なので、直すのは依存する側。範囲の中のバージョンは、呼び出し側が何も合わせなくてよい変更だけで上がる。（決定日：記録なし）

### 3. 差し替えるときは、宣言の1件も差し替える

判断先や依頼先を別の人のスキルに差し替えるときは、宣言の1件も差し替える。core-logic は作成者で名前が変わるので、委任表の見出しのスキル名も書き替える。バージョンの範囲は、スキルごとに1つ持つ。

1. 記録なし
