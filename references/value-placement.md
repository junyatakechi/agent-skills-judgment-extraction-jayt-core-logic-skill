# 値の置き場所

## 扱うこと

値を書くとき、ロジックスキル・取り決めファイル・`.env`・材料のどこに置くか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 1-4・1-5・3-1 を写した。（出典：人の判断を切り出すAIスキルの設計_v2.2.2 の1-4・1-5・3-1@2026-11-13）

### 1. 誰が決めた値かで、置き場所を決める

置き場所は、その値を誰が決めたかで分ける。core-logic か generic-logic かでは分けない。

| 値の種類 | 誰で決まるか | 例 | 正（大元） |
|---|---|---|---|
| 判断定数 | ロジックスキルの作成者 | 停滞判断の窓 14日 | 判断ファイルの「判断定数」の表。判断に使う道具はその表を実行時に読む。手続きに使う道具はコードの定数が正（→ 答え方3） |
| 数学・物理の定数 | 誰が決めても同じ | t分布の表 | 道具のコード |
| 誰もが共有する環境の仕様 | 環境の提供元 | Web APIのレート制限 | 道具のコードの定数 |
| 導入先の環境の構成 | スキルを入れた個人や組織 | OS・シェル・使うAIのツール・機器の機種 | アプリケーションスキルの取り決めファイル（`conventions/`）に書くか、実行時にAIが確かめる |
| 導入先の環境の設定値 | スキルを入れた個人や組織 | DBのID・トークン・カレンダーのID | プロジェクトのフォルダ直下の `.env` |
| 導入先の環境の取り決め | 導入先や判断の対象の運用 | 読むDBと列・記録の書き方・本人の語の一覧 | アプリケーションスキルの取り決めファイル（`conventions/`） |
| 対象の値（属性・記録） | 判断の対象 | 目標・毎日の体重 | 導入先にある入力済みデータ（NotionのDB・カレンダー・プロジェクトのフォルダに置いたJSONなど）または、チャットで本人から聞く |

ロジックスキルの外に置く値（導入先の環境・対象の値）を、ロジックスキルに書かない。設定値はロジックスキルに材料としても渡さない。それ以外は、判断に要るときに材料として写しを渡す。

1. （根拠）ロジックスキルの外に置く値を書くと、その導入先や対象の専用になり、そのまま渡せなくなる。（決定日：記録なし）

### 2. 似た値は、誰が決めたかで見分ける

判断定数・取り決めの定数・対象の値は、どれも人が決めることがある。見分けるのは、誰が決めたか。作成者が判断のために決めた値は判断定数、導入先や判断の対象の運用で決まる定数は取り決め、判断の対象が決めた値は対象の値にする。例：良いペースの減り幅（30日で1.5〜3.0kg）は判断定数、食事の記録の書き方の印は取り決め、目標体重は対象の値。境目にある値は、作成者が決めた部分があるかで決める。例：Web API が日付の境目をどう扱うかは誰もが共有する環境の仕様だが、取りこぼさないために前後へ何日足して取るかは判断定数にする。

1. 記録なし

### 3. 判断定数の正は、道具の種類で変わる

判断に使う道具（`judge.py`）は、判断ファイルの「判断定数」の表を実行時に読み、値が見つからなければ、どの表のどの名前が無いかを示して止まる。手続きに使う道具は表を読まず、コードの定数を正にする。手続きに使う道具の判断定数も、判断ファイルの「判断定数」の表に写しとして残す。表の上に正がコードの定数であることを書き、決めた理由は表の「理由」の列に書く。

1. （根拠）手続きに使う道具は多くのスキルが読み込むたびに import するので、表の書き損じが1つあるだけで、それを使うすべてのスキルが止まる。人が判断定数を探すのは判断ファイルなので、表から消すと、判断定数があることに気づけなくなる。（決定日：記録なし）

### 4. ロジックスキルの外に置く値は、3つの置き場に分ける

| 置き場 | 置くもの | 例 |
|---|---|---|
| 導入先のデータ（または、チャットで本人から聞く） | 対象の値（属性・記録）。対象について読まれる値 | NotionのDBの体重記録・カレンダーの食事の予定・プロジェクトのフォルダに置いたJSONの目標体重・チャットで聞いた今日の体調 |
| アプリケーションスキルの取り決めファイル（`conventions/`） | 導入先の決まり（定数や対応付け）。何がどこにあり、どう書かれているか | 読むDBと列・食事の記録の書き方・本人の語の一覧（「おやつ」は間食） |
| プロジェクトのフォルダ直下の `.env` | IDとトークンの実値 | DBのURL・カレンダーのID・トークン |

データと取り決めは、決まりかどうかで見分ける。本人の語の一覧は対応付けなので取り決めファイル、目標体重は本人について読まれる値なので導入先のデータに置く。プロジェクトのフォルダ直下の `.env` は、プロジェクトのスキルで共有し、キーの中身は各スキルの `.env.example` が持つ。同じプロジェクトのフォルダに置くときも、`.env` とデータのファイルを分ける。

1. （根拠）語の一覧は「この語は間食」という対応付けで、取り決めファイルは定数や対応付けなどの決まりを書く場所である。目標体重は、体重記録・食事記録と同じく、導入先のデータから取ってくる値である。`.env` は、スキルに書けないIDとトークンの置き場で、対象の値の置き場ではない。（決定日：2026-11-13）

### 5. 本人の語の一覧は、材料で渡し、ロジックスキルが当てはめる

本人の語の一覧は、材料で渡し、ロジックスキルが当てはめる。アプリケーションスキルが語で記録を判定し、判定した印を渡さない。

1. （根拠）何をどの語でまとめるかが判断で、判断はロジックスキルが持つ。（決定日：2026-11-13）
2. （原因）ダイエット進捗の評価アプリが、記録ごとに `種類`・`入手元`・`いつもの枠` を判定して渡していて、何を間食・外食・普段の食事とするかの判断が、アプリのコードの中にあった。（発生日：2026-11-10）

### 6. 環境は2種類に分け、導入先の環境はさらに3つに分ける

環境は、共有した先で変わるかで、誰もが共有する環境と導入先の環境の2種類に分ける。導入先の環境は、構成（どのOS・ツール・機器を使っているか）・設定値・取り決めの3つに分ける。

|  | 誰もが共有する環境 | 導入先の環境 |
|---|---|---|
| 中身 | 仕様と癖 | 構成・設定値・取り決めの3つ |
| 例 | Web API・OS・言語の実行環境の仕様と癖 | 構成は、OSがWindows・使うAIのツール・体組成計の機種。設定値は、DBのURL・カレンダーのID・トークン。取り決めは、読むDBと列・記録の書き方・本人の語の一覧 |
| ロジックスキルとの関係 | generic-logic は依存してよい。core-logic は、判断に使う道具を動かす言語の実行環境だけを、標準ライブラリの範囲で使ってよい | どのロジックスキルにも書かない。構成と取り決めは、判断が環境の性質に依るときに、材料として写しを受け取る。設定値は、材料としても受け取らない |
| 置き場所 | 道具のコード | 構成は、取り決めファイルに書くか、実行時にAIが確かめる。設定値は、プロジェクトのフォルダ直下の `.env`。取り決めは、取り決めファイル |

仕様と、どれを使っているかを分ける。Windows のふるまいは誰もが共有する環境、この導入先が Windows を使っていることは導入先の環境に入る。

1. （根拠）各スキルは OS・シェル・使うツール・機器の機種を材料で受け取っているのに、設計文書の 1-4 にはどちらにも書かれていなかった。Windows のふるまいには依存してよいが、Windows を使っていることは材料で受け取る、という違いを説明できなかった。（決定日：2026-11-13）
