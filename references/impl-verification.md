# 書き替えたあとの確かめ方

## 扱うこと

スキルを作った・直したあと、何で確かめるか

## 答え方と理由

### 0. 判断全体

実装の判断。

- （根拠）設計文書は型を定めるが、作ったあとにどう確かめるかは書いていない。（決定日：2026-10-29）

### 1. 計算で型を確かめてから、設計文書の章と見比べる

スキルを作った・直したあとは、まず計算で型を確かめる。判断ファイルには `judgment-file`・`reasons`・`impl-judgment-details`、ロジックスキルには `logic-skill-shape`、アプリケーションスキルには `app-skill-shape` を流し、題材にした記録から作ったときは `impl-example-values` も流す。`問題` が空になるまで直す。材料は、確かめるスキルのフォルダを呼び出し側がまとめて作る。

```bash
python -I -c "import json,os,sys; d=sys.argv[1]; f={os.path.relpath(os.path.join(r,n),d).replace(os.sep,'/'): open(os.path.join(r,n),encoding='utf-8').read() for r,_,ns in os.walk(d) if '.git' not in r and '__pycache__' not in r for n in ns if n.endswith('.md') or n=='LICENSE'}; json.dump({'ファイル': f, '種類': sys.argv[2]}, open(sys.argv[3],'w',encoding='utf-8'), ensure_ascii=False)" <スキルのフォルダ> <core-logic|generic-logic|app> <材料.json>
```そのあと、計算では確かめられない中身（答え方の書き方・手順の組み方・理由の種類の選び方）を、写す判断ごとに設計文書の章と1つずつ見比べる。確かめたことと、確かめていないことを、本人に伝える。

1. （原因）型を目で確かめただけで終えたら、本人に見直しを頼まれるまで、未決の指し方・手順のIDの書き方・却下した案の理由の抜けなど5か所のずれに気づかなかった。計算で確かめると、目で確かめたあとのファイルにもずれが見つかった。（発生日：2026-10-28）

### 2. 題材から切り出したときは、理由ごとに題材の書いてある所を確かめる

題材にした記録（ISSUE など）から判断を切り出したときは、理由ごとに、題材のどこに書いてあるかを1つずつ確かめる。見つからない理由は「記録なし」に戻し、見つからない日付は「記録なし」にする。計算では題材と見比べられないので、AIが確かめる。

1. （原因）ISSUE から靴のサイズ選びのスキルを作ったとき、ISSUE に無い理由と日付を4か所補った。型の計算では拾えず、目で見直して直した。（発生日：2026-10-29）

### 3. アプリケーションスキルは、実データで手順を1回通す

アプリケーションスキルを作った・直したあとは、型の確認に加えて、実データで手順を1回通す。材料のスクリプトが記録を読めるか、判断の答えが出力の様式の表に収まるかを確かめる。

1. （原因）ダイエット進捗の評価アプリを中核判断に合わせて直したとき、型の確認はすべて通ったが、実データで通して初めて、普段とは違う食事が30日中28日に当たり、日ごとの表が成り立たないことが分かった。カレンダーの店名が `at`・`from` で書かれていることも、実データを見るまで分からなかった。（発生日：2026-11-11）
