# 道具の種類

## 扱うこと

道具を作るとき、判断に使う道具と手続きに使う道具のどちらにし、どのスキルに置くか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。`judge.py` の決まりは、この判断では答えない（→ [判断に使う道具の作り方](judge-tool.md)）。

- （知見）設計文書の 1-3 と 5-3 の道具の表を写した。（出典：S1）
- （知見）道具で強制できる判断の例は、設計文書の 5-3 を写した。（出典：S2）

### 1. 誰が使うかで分ける

ロジックスキルが判断の中で使うのが判断に使う道具、アプリケーションスキルが手続きの中で使うのが手続きに使う道具。値の変換だけをする道具も、手続きの中で使うなら手続きに使う道具。

| | 判断に使う道具 | 手続きに使う道具 |
|---|---|---|
| スキルの外の状態 | 読み書きしない。読むのは自分の判断ファイルと渡された材料だけ | 読み書きしてよい |
| 同じ入力なら | 必ず同じ値を返す | 外の状態によって変わることがある |
| 持ってよいスキル | core-logic・generic-logic | generic-logic・アプリケーションスキル |
| 呼び方 | 材料をJSONファイルにまとめて渡し、結果を標準出力で受け取る | Pythonならimportし、シェルや他の言語からはスクリプトを起動する。呼び出し側は自前の薄いラッパーを持たない |
| 導入先の環境 | 受け取らない | トークンなどはプロジェクトのフォルダ直下の `.env` から読む。同じ名前の環境変数を優先する。操作する対象のIDは引数で渡す |
| 失敗したとき | 必須の材料が無ければ、足りない材料の名前をJSONで返して止まる | 例外で返し、続けるか止めるかを呼び出し側が選ぶ |

1. （根拠）同じ材料なら必ず同じ値を返してほしい計算は、判断に使う道具としてコードに置く。厳密さが要るのは、道具の手前だけにする。（決定日：記録なし）

### 2. 道具で強制できる判断は道具に、できない判断は使い方として答える

手続きに使う道具で強制できる判断（ページ送り・心拍を取る範囲の分割など）は、道具の中に実装し、理由を判断ファイルに書く。強制できない判断は、ロジックスキルが道具の使い方として答え、呼び出し側のAIエージェントが守る。

1. 記録なし

### 3. 関数の一覧は docstring に、import の仕方は SKILL.md に書く

手続きに使う道具は、各モジュールの冒頭の docstring に、公開する関数を1行ずつ書く。import の仕方は SKILL.md の「手続きに使う道具」だけに書く。導入先の環境が足りないことは、道具の例外で返す。

1. （根拠）2か所に書くと、関数を足したときに片方だけが直される。（決定日：記録なし）

### 4. まだ切り出していない判断の計算は、アプリケーションスキルに置いてよい

まだ切り出していない判断の計算は、切り出すまでアプリケーションスキルに置いてよい。切り出したら、判断に使う道具としてロジックスキルへ移す。

1. 記録なし
