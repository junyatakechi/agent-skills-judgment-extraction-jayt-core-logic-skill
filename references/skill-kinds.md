# スキルの種類

## 扱うこと

スキルを作るとき・判断を切り出すとき、ロジックスキルとアプリケーションスキルのどちらにし、core-logic と generic-logic のどちらにするか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 1-1・1-2・2-1 を写した。（出典：S1）

### 1. 判断を持つならロジックスキル、外部に判断を委ねて実行するならアプリケーションスキル

1つの区切られた文脈について、作成者が特別に切り出した判断だけを持つなら、ロジックスキル。何かを達成するために、外部に判断を委ねながら実行するなら、アプリケーションスキル。

| | ロジックスキル | アプリケーションスキル |
|---|---|---|
| 持つもの | 判断・その理由・判断に要る計算 | 委任表・参照表・まだ切り出していない判断の表・材料の取得と変換・手順・依頼表・依存の宣言・取り決めファイル |
| 持たないもの | 判断の対象とその値・導入先の環境。core-logic は、データの取り方・保存・手順も持たない | 切り出した判断・その計算 |
| 依存 | 他のスキルに依存しない | ロジックスキルに依存する。ほかのアプリケーションスキルにも、手順として依存してよい |
| 共有するとき | そのまま渡す | 環境に合わせて作り直してよい |
| 更新する人 | 人 | AIエージェントに任せてよい |

中核判断を、実行時にAIエージェントへ任せない。判断の答えを、アプリケーションスキルに書き写さない。ロジックスキルは同一性を扱わない。まだ切り出していない判断は、アプリケーションスキルに判断ファイルの形で置いてよい。

1. （根拠）中核判断を実行時にAIエージェントへ任せると、一般論しか返ってこない。答えを書き写すと設計時に固定され、判断を更新しても伝わらない。（決定日：記録なし）

### 2. 人によって答えが分かれるなら core-logic、誰でも同じ答えなら generic-logic

人によって答えが分かれる判断は core-logic。知れば誰でも同じ答えになるが、AIエージェントの一般知識にはまだ無い判断は generic-logic。

| | core-logic | generic-logic |
|---|---|---|
| 使い方 | 中核判断の委任表の行ごとに、判断先の判断ファイルを読んで当てはめる | 参照表から、その業務領域の作業に入る前に読み込み、作業に当たる判断ファイルに従う |
| 依存してよい環境 | 判断に使う道具を動かす言語の実行環境だけ（標準ライブラリの範囲） | 公開された環境（Web API・OS・言語の実行環境など）だけ |
| 共有したとき | 混ぜずに並べ、差し替えて使う | 混ぜて1つに育てる |

1. （根拠）一般的な業務知識は、みんなの知見を足すほど正しくなる。中核判断は、混ぜると平均化されて一般論に戻る。（決定日：記録なし）

### 3. 切り出すきっかけは、目的と実行結果の齟齬に置く

アプリケーションスキルが実行し、人が目的と実行結果の齟齬を見つけたら、その所に切り出すべき判断がある。切り出し先は、人によって答えが分かれるかで決める。

1. （根拠）まだ切り出していない判断はAIエージェントが一般論で下すので、判断を書ききる前から動く。そこで出た齟齬が、切り出すべき判断を見つける手がかりになる。（決定日：記録なし）
