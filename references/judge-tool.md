# 判断に使う道具の作り方

## 扱うこと

`judge.py` を作る・直すとき、呼び方・失敗の返し方・判断定数の読み方をどうするか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 5-3 の judge.py の表と、入口と中身の分け方と、その理由を写した。（出典：人の判断を切り出すAgent Skillsの設計_v3.0.0 の5-3@2026-11-18）

### 1. 入口は `scripts/judge.py` の1本にし、中身を判断ごとのファイルに分け、決まりの表に従う

| 項目 | 決まり |
|---|---|
| 置き場所と名前 | 入口は `scripts/judge.py` の1本。判断ごとの計算は `scripts/judgments/<判断>.py` に置き、名前を `references/<判断>.md` とそろえる。共通の部品（足りない材料の返し方・判断定数の読み方・依存先の読み込み）は `scripts/judgments/_common.py` に置く |
| 判断ごとのファイル | `judge(m)` を持ち、材料を受け取って結果を返す。引数の読み方と終わり方は持たず、入口に任せる。依存先の計算は、共通の部品の読み込みで呼ぶ |
| 読み込み | 入口は、頼まれた判断と、その依存先のファイルだけを読み込む。受け付ける判断は、`scripts/judgments/` にあるファイルから決める |
| 呼び方 | `uv run <skill-dir>/scripts/judge.py <判断> <材料.json>` |
| 第1引数 | 判断のファイル名（拡張子を除く）。計算を持つ判断だけを受け付ける |
| 第2引数 | 材料のJSONファイル。キーと形は、判断ファイルの「求める材料」に従う |
| 結果 | 標準出力にJSONで出す。Markdownで返す判断は、判断ファイルの「計算」にそう書く |
| 必須の材料が無いとき | `{"足りない材料": ["<材料の名前>", ...]}` を標準出力に出し、終了コード2で止まる |
| 必須でない材料が無いとき | 計算できる範囲を返し、結果の `"足りない材料"` に名前を入れる |
| 使い方の誤り（無い判断・引数の数） | 使い方を標準エラーに出し、終了コード1で止まる |
| 判断定数 | 判断ファイルの「判断定数」の表を実行時に読む |
| 依存 | 言語の標準ライブラリだけで動かす。外部のライブラリにも、ほかのスキルにも依存しない |

1. （根拠）外部のライブラリを入れる手間を、導入先に求めない。決まりはこの判断だけが持ち、SKILL.md には呼び方だけを定型文で置く。（決定日：記録なし）
2. （原因）2つの core-logic で、足りない材料の返し方が「標準エラーと終了コード1」と「JSONと終了コード2」に割れていた。（発生日：記録なし）
3. （根拠）入口を1本にして、失敗の返し方と依存の解決を1か所で持つ。実行を許す権限も1つの形で書け、無い判断の名前には受け付ける判断の一覧を返せる。中身を判断ファイルと同じ名前に分けると、計算の場所が名前で分かり、1つの判断を直すときに全体を読まずに済む。頼まれた判断と依存先だけを読み込むと、1つの判断の書き損じで、ほかの判断の計算まで止まらない。（決定日：2026-11-18）
