# README

## 扱うこと

README を書くとき、どの章に何を書き、何を書かないか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 3-3 を写した。（出典：人の判断を切り出すAIスキルの設計_v2.2.3 の3-3@2026-11-16）

### 1. README は人が読み、AIが読むことは書かない

README は人が読む。このスキルが何をするかと、導入の手作業を書く。導入の手作業は README だけが持つ。AIが読むことは書かず、SKILL.md と判断ファイル（アプリケーションスキルでは取り決めファイルも）に書く。

1. 記録なし

### 2. 章は判断定数 `README の章` の順で書く

`# <スキル名>` のあとに、判断定数 `README の章` を、この順で書く。書くかどうかは、「この章を消したら、人が導入や共有で困るか」で決める。

| 章 | 書くこと | 種類による違い |
|---|---|---|
| `# <スキル名>` | 何をするスキルか。1〜2文 | なし |
| `## 必要なもの` | スキルの外で人が用意するもの | アプリケーションスキルは、「`SKILL.md` の frontmatter の `metadata.dependencies` に書いてある依存するスキル」の1行を置く |
| `## インストール` | クローンするコマンドと、置く場所 | なし |
| `## セットアップ` | 導入の手作業の手順 | 手作業が無ければ「なし」。アプリケーションスキルは、最初の手順に「依存するスキルを、このスキルと同じ `skills/` フォルダに並べて置く」を書く |
| `## 使い方` | 名前で指名して呼ぶこと | アプリケーションスキルは、スキル名だけを示す。ロジックスキルは、主にアプリケーションスキルから呼ばれることと、直接聞くときの頼み方の例を2〜3個書く |

1. 記録なし

### 3. 正がほかにあるものは、写さずに指す

依存するスキルは依存の宣言が、`.env` のキーの中身は `.env.example` のコメントが、ライセンスは `LICENSE` が持つ。README に写さない。

1. （根拠）2か所に書くと、片方だけが直される。（決定日：記録なし）

### 4. 「セットアップ」の見出しと小見出しの名前を変えない

「セットアップ」の見出しと、その下の小見出しの名前は変えない。

1. （根拠）アプリケーションスキルの手順と設定の不足の判断が、README の見出しを名前で指す。（決定日：記録なし）

### 5. 書かないものを書かない

使い方に、具体的なアプリケーションスキルの名前を書かない。自明なこと、ファイルの一覧、設計の説明、道具の一覧と呼び方、判断の中身、手順の中身、ライセンスを書かない。どの種類のスキルも、フォルダに `LICENSE` を持つ。

1. （根拠）ロジックスキルだけを使う導入先もあり、アプリケーションスキルは導入先ごとに違う。ほかのものは、それぞれ正がほかにある。（決定日：記録なし）
