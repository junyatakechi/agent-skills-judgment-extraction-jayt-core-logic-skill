# 判断の移し替え

## 扱うこと

齟齬が見つかったとき・判断を別のスキルへ移すとき、どこへ切り出し、表とIDをどう直すか

## 答え方と理由

### 0. 判断全体

設計文書を写す判断。

- （知見）設計文書の 2-2 と 6-4 のIDの付け方を写した。（出典：人の判断を切り出すAgent Skillsの設計_v3.1.0 の2-2・6-4@2026-11-18）

### 1. 移り変わりごとに、決まったことをする

| 移り変わり | きっかけ | すること |
|---|---|---|
| アプリケーションスキル → core-logic | 齟齬の原因が、人によって答えが分かれる判断だった | core-logic に切り出し、行を、まだ切り出していない判断の表から中核判断の委任表へ移す。IDも一緒に移す |
| アプリケーションスキル → generic-logic | 齟齬の原因が、誰でも同じ答えになるがAIエージェントが知らない判断だった | generic-logic に切り出し、行を、まだ切り出していない判断の表から消す。参照表にそのスキルの行が無ければ足す。そのIDを指していた手順は、参照表のIDを参照する形に直す。消したIDは欠番にする |
| core-logic → generic-logic | 中核判断が成熟し、誰がやっても同じ答えになった | generic-logic へ移す。委任表から行を消し、参照表にそのスキルの行が無ければ足す。そのIDを指していた手順は、参照表のIDを参照する形に直す。消したIDは欠番にする |
| generic-logic → core-logic | 一般的な業務知識が膨らみ、人によって答えが分かれる判断が混ざってきた | その判断を core-logic に切り出す |
| core-logic・generic-logic → 削除 | 判断が、AIエージェントの一般知識になった | ロジックスキルを外して実行し、齟齬が出ないことを確かめてから削除する |

1. （根拠）混ぜたまま共有すると、視点が平均化される。（決定日：記録なし）

### 2. IDは表をまたいで通し番号にし、付け直さない

IDは、中核判断の委任表とまだ切り出していない判断の表をまたいで通し番号にし、区分を入れない。一度付けたら付け直さない。行を消しても番号を詰めない。

1. （根拠）区分をIDに入れると、移すたびにIDが変わり、手順の参照が壊れる。詰めると、古い参照が別の行を指す。（決定日：記録なし）
